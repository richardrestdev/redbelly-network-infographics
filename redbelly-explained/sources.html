03 DBFT consensus

Printed source line: Redbelly whitepaper / research hub

#What the infographic saysPrinted linesPageSupporting quote
1DBFT stands for Democratic Byzantine Fault Tolerant consensus.“Democratic Byzantine Fault Tolerance”Redbelly whitepaper (PDF, 28 Aug 2025)“Democratic Byzantine Fault Tolerant (DBFT) consensus”
2DBFT is how the nodes reach consensus on the next block, and it is leaderless.“How Redbelly’s nodes agree on the next block, with no leader.”
“No leader”		Redbelly whitepaper (PDF, 28 Aug 2025)“As a leaderless consensus algorithm, it eliminates single points of failure”
3In classical blockchains nodes compete; one block wins and the rest is wasted.“Classical chains”
“Nodes compete”
“One block wins. The rest is wasted.”		Redbelly whitepaper (PDF, 28 Aug 2025)“In classical blockchains, participants solve consensus by having different participants engage in ‘fierce’ competition: proposing their own block and trying to impose it on the system. If they succeed, then all other participants lose: their block is the only one appended at the next available index of the chain. This is a waste of resources as only one participant succeeds and the rest fail.”
4DBFT nodes cooperate: their transactions are combined into one superblock.“Transactions join a superblock.”Redbelly whitepaper (PDF, 28 Aug 2025)“Redbelly nodes, on the other hand, solve consensus by combining distinct sets of transactions into a ‘superblock’ in a leaderless manner”
5Redbelly consensus is collaborative instead of competitive.“Nodes cooperate”Redbelly whitepaper (PDF, 28 Aug 2025)“Redbelly consensus is collaborative instead of competitive”
6No leader: every node plays a similar role.“No leader”
“Every node plays a similar role.”		Research: DBFT, Efficient Leaderless Byzantine Consensus“each node plays a similar role in the execution of the consensus”
7No forks: once decided, a block is final.“No forks”
“A decided block is final.”		Redbelly whitepaper (PDF, 28 Aug 2025)“It cannot fork and has been mathematically proven to be correct through a process of formal verification through parameterised model checking”
8Finality is deterministic: a confirmed transaction cannot be reversed.“A decided block is final.”Redbelly asset tokenisation“Deterministic finality ensures transactions are confirmed once and cannot be reversed”
9Fault tolerant: proven (by model checking) safe for any number of nodes while fewer than 1 in 3 are faulty. Condition printed: “under 1 in 3”.“Fault tolerant”
“Proven safe if under 1 in 3 nodes are faulty.”		Research: Holistic Verification of Blockchain Consensus“for any number n of processes and any number f < n/3 of Byzantine processes”
10The proof covers safety (and liveness) for any parameter.“Proven safe if under 1 in 3 nodes are faulty.”Research: Holistic Verification of Blockchain Consensus“we formally verify, for any parameter, not only the safety properties of the Redbelly Blockchain consensus but also its liveness”
